# 星河轮换联赛 · 评分分析

一个**纯本地**的选手评分与校验应用：用虚构的多人团队比赛，估计随时间变化的个人能力、
阵容组合表现和不确定区间，并用已知真值检查估计结果。

全程使用生成数据，不连接任何真实赛事、投注或第三方服务。

## 快速开始

需要 Python ≥ 3.10 与 Node ≥ 20。后端只用 Python 标准库，前端只用 Vite。

```bash
# 1) 依赖
python3 -m venv .venv && .venv/bin/pip install pytest   # 仅测试需要第三方包
npm install

# 2) 生成确定性虚构数据集（同一 seed 的比赛与真值完全一致）
npm run sample                       # → data/generated/season.json（166 行导入、159 场有效比赛）

# 3) 启动本地 JSON API  http://127.0.0.1:8765
npm run api

# 4) 另开终端，启动页面  http://127.0.0.1:5173   （/api 代理到 8765）
npm run dev
```

页面顶部会显示数据是否就绪。若先开了页面，会提示在项目根目录运行 `npm run api`。

生产构建与测试：

```bash
npm run build    # 输出到 web-dist/（静态文件；仍需要 npm run api 提供 /api）
npm test         # 37 个 Python 测试：引擎、重放、榜单、诊断、HTTP 接口
```

首次打开某一屏或改动漂移假设时，服务端会现场计算并缓存迭代结果（逐场帧近似约 0.1 s、
窗口联合约 1.7 s；窗口的漂移网格重跑约 7 s），因此第一次切换会看到「重算中」，
同一配置随后立即返回。

## 模型

每场比赛的进球数由两个独立泊松分布产生：

```
eta_A = log(base_goals) + mean_{i∈A} s_i + g(lineup_A)
eta_B = log(base_goals) + mean_{j∈B} s_j + g(lineup_B)
y_A ~ Poisson(exp(eta_A)),  y_B ~ Poisson(exp(eta_B))
```

- `s_i`：选手 i 随时间变化的能力（对数尺度上对己方期望进球的提升）；
- `g(lineup)`：经常出现的**确切阵容**的组合项（≥2 人、重复出现才估计）；
- 平局不需要特殊处理：两个独立泊松计数自然产生平局，画面上给出的是三项概率。

**没有主场项**：数据不包含主客场，模型也不假设。

### 时间漂移

两场比赛之间，每位选手的能力方差按 `drift_sd² × 天数` 增长。缺席期间没有新证据，
所以**区间只会变宽、不会变窄**——久未参赛不会凭空提高确定性。`drift_sd` 是页面上可调的
假设（滑杆），数据集的真值为 `0.01`，默认工作配置取 `0.04`。

### 两种更新方式

| | 逐场近似 `ApproxFilter` | 窗口联合 `WindowFilter` |
|---|---|---|
| 每次更新 | 单场似然上的对角 Laplace 更新 | 最近 `window=8` 场的联合 Newton/Laplace 拟合 |
| 参数相关 | 忽略（每人用自己的先验） | 保留完整后验协方差 |
| 组合项 | 每场局部更新 | 与个人能力在同一拟合里估计 |
| 每场耗时（模型内计时） | ~0.03 ms | ~10 ms |

窗口滤波器保留了「同一阵容共享一个似然」的全部协方差，因此队友之间、个人与组合项之间的
折衷是可解释的；近似滤波器更快，但会低估相关带来的不确定性。

### 可识别性

固定 `b = log(base_goals)`，所以绝对水平可识别。若两个群组**从未交手**，它们之间的
绝对水平只由先验基准对齐，没有数据支撑——模型把这类群组单列提示，不把跨组分数当成同一
尺度上的可信比较。同理，若三人永远同队出场，任何「把功劳分给谁」的规则都同样符合数据：
个体水平不可识别，应只读**阵容合计**（成员均值 + 组合项）。页面把成员估计跨度（本数据
上恰为 0.000）、两种方式的阵容合计及其 90% 区间、组合项与真值的对比放在一起；窗口的区间
来自联合后验协方差，近似的来自方差直接相加，二者之差正好说明绑定带来的相关有多重要。

## 数据

`npm run sample` 生成的确定性数据集（seed `75826`）刻意包含任务要求的全部情形：

| 情形 | 内置样例 |
|---|---|
| 主池轮换 | 26 人、113 场，2–5 人对 2–5 人 |
| 完全未交手群组 | `Q001…Q004` 只在自己组内比赛（8 例） |
| 同队绑定 | `B001|B002|B003` 永远同队，另有固定组合项真值 |
| 平局 | 势均力敌、低比分的对局（有效比赛中平局占比 19.5%，真值元信息 19.3%） |
| 重复导入 | `D001…D006, D900` 共 7 行与已有比赛同指纹，导入时剔除 |
| 同对阵不同比分 | `C001` 与 `M0056` 冲突：两行都保留，提示人工确认 |
| 长期缺席 | 魏朔（`P018`）第 66–128 天无比赛 |
| 已知状态突变 | 6 名选手在中段发生 0.55–0.85 的真实能力跳变 |

去重使用与主客场方向无关的指纹（同日、同两套阵容、同比分）；同一对阵不同比分不合并，
记为冲突。跨组连通性用并查集求连通分量，诊断据此判断「完全未交手」。

## 更正与重放

每场比赛在每 10 场保存一个检查点。更正一场早期赛果时：

1. 结果簿追加一个新版本（`ResultBook`，append-only），**不修改**原记录；
2. 从「不晚于该场的最新检查点」恢复滤波器状态，重放其后的所有比赛，得到新的运行版本；
3. 运行版本记录 `parent_revision` / `replayed_from` / `history` 血缘；
4. 已发布的榜单（append-only JSONL）保持原样，因为它们是**当时那版赛果**的发布物。

页面在更正后同时展示两种方式的重放报告：使用了哪个检查点、重放了多少场、终局最大变化、
哪些选手的轨迹移动，以及移动前后的轨迹叠加图。旧的运行版本和旧榜单都能在「运行版本与血缘」
里查到并导出 JSON。

## 界面

7 个视图，全部只读本地 API：

1. **逐场回放**——滑杆/播放逐场推进；查看赛前预测、赛后更新、个人轨迹与 90% 区间（叠加真值）、
   当前排名（不交手的群组、绑定阵容会被标记）。
2. **方法对比**——两种更新的误差曲线、校准与耗时、终局差异，以及**漂移假设敏感性**
   （只改 `drift_sd`，重跑整个赛季，同时看 RMSE 与 90% 覆盖率）。
3. **校验**——每一问都用数字回答：一步精确解 vs 对角近似、解析梯度 vs 中心差分、
   窗口截断稳定性，并附中心差分与覆盖率。
4. **更正与重放**——更正表单、两种方式的重放报告与轨迹图、运行版本血缘、结果簿与导出。
5. **发布榜单**——发布当前榜单为不可变版本，查看每个版本的成绩、90% 区间、配置指纹与赛果版本。
6. **情景样例**——任务要求的所有边界情形集中展示，并可直接跳转回放。
7. **数据与导入**——数据集说明、导入审计（重复/冲突）、选手与分组、比赛表（生效版本）、复现命令。

明暗主题各自独立选色（不是自动反色），并同时支持 `prefers-color-scheme` 与手动切换；
每个图都可通过「查看数据表」得到数值表的等价可读版本。

## 校验与实测结果

默认配置（`drift_sd = 0.04`）、159 场有效比赛、33 名选手：

| 指标 | 逐场近似 | 窗口联合 |
|---|---|---|
| RMSE（对照真值） | **0.4999** | 0.5147 |
| MAE | 0.4222 | 0.4351 |
| 90% 区间覆盖率（目标 0.90） | 87.3% | 83.3% |
| 终局 RMSE（出场 ≥5 场） | **0.4018** | 0.4280 |
| 总耗时（模型内计时） | 0.005 s | 1.70 s |

- **近似在本数据集上 RMSE 更低**，这是如实结果而不是预设结论；页面直接说明，并给出解释
  （漂移较强时，只做局部更新的近似对旧信息累积更少）。窗口联合的价值在于每次都给出一致的
  联合后验，并在阵容共享信息时更可解释。
- **一步精确对比**（同一场、同一先验）：最大 |差| 在 0.000–0.054 之间，最大 z ≈ 0.13，
  即对角线近似在单场上误差很小；它的主要代价体现在长期协方差与绑定阵容上。
- **梯度校验**：16 个参数抽查 6 个，解析梯度与中心差分的最大误差为 0.0（机器精度），
  协方差不对称度 0.0。
- **窗口截断**：以 8 场为基准，用 16 / 32 / 全部历史时终局 RMS 差为 0.099 / 0.173 / 0.395，
  说明更长的历史确实会改变答案，`W=8` 是可辩护的选择而非任意值。
- **绑定阵容**：成员估计跨度 0.000（真值跨度 0.642）。阵容合计：近似 0.918（90%：0.499–1.337），
  窗口联合 0.902（90%：0.557–1.248）。两者点估计几乎一致，但窗口用完整后验协方差得到
  σ 0.210，而把成员与组合项的方差直接相加是 σ 0.272——负协方差被前者正确计入，
  所以窗口对「合计」给出更窄、而非更盲目的区间。组合项约 0.35–0.37，真值 0.35。
- **孤立群组**：组均值估计 −0.256，真值 −0.259，水平偏差 0.003，但这一对齐仅由先验决定。
- **缺席**：魏朔第 66–128 天无比赛，期间 σ 随漂移单调增大，复出后重新收窄。

如果拖动漂移滑杆，以上数字会变——**漂移敏感性图**会同时显示两种方式在全网格上的
RMSE 与覆盖率，便于判断当前假设是否合理（例如覆盖率何时接近 0.90）。

## 架构

```
rating/
  model.py        数据模型、去重指纹、连通分量、结果簿（append-only 版本）
  linalg.py       纯 Python 的 Cholesky / 求解 / 求逆
  generator.py    确定性虚构数据生成（含全部边界情形与真值路径）
  engine.py       泊松模型、逐场近似滤波器、窗口联合滤波器
  run.py          顺序运行、每 10 场检查点、更正后从检查点重放
  analysis.py     真值评分、一步精确对比、梯度校验、截断曲线、响应速度
  diagnostics.py  未交手群组、绑定阵容、平局、重复/冲突
  boards.py       不可变发布榜单（JSONL 追加）
  server.py       标准库 ThreadingHTTPServer 的本地 JSON API（127.0.0.1:8765）
scripts/build_sample.py   生成 data/generated/season.json
web/                      Vite + 原生 JS/DOM 页面（无框架、无图表库）
  src/charts.js           自绘 SVG 折线/区间条/小多图，含十字线与 tooltip
  src/panels/*.js         7 个视图
tests/                    37 个 pytest 用例（引擎、生成器、重放、HTTP）
```

数据目录：

```
data/generated/season.json   种子输入数据（随仓库保存，保证可复现）
data/runs/                   运行版本（生成物，已 gitignore）
data/boards/                 发布榜单（生成物，已 gitignore）
data/results.json            结果簿（生成物，已 gitignore）
```

「数据与导入」页与更正页都提供 **重置本地数据**：删除上述生成物并恢复原始赛果，
种子数据集本身不会被改动。

## API

本地 JSON，全部只读 `data/` 下的文件，不访问网络：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/bootstrap` | 数据集、选手、比赛、配置、诊断、真值元信息 |
| GET | `/api/run?method=` | 轻量逐场列表（概率、比分、耗时） |
| GET | `/api/frames?method=` | 全部逐场帧（每场每人的前后均值/σ、概率） |
| GET | `/api/frame?method=&index=` | 单场帧 |
| GET | `/api/player?method=&id=` | 单选手轨迹（含真值与是否出场） |
| GET | `/api/compare` | 两种方式的评分卡、逐场误差、终局差异、耗时 |
| GET | `/api/checks` | 全部校验项（一步、梯度、截断、响应、缺席、绑定、孤立组） |
| GET | `/api/diagnostics` | 分组、绑定、平局、重复与冲突 |
| GET | `/api/scenarios` | 边界情形样例 |
| GET | `/api/sweep?method=` | 漂移假设网格重跑（RMSE/覆盖率/耗时） |
| GET | `/api/revisions` | 运行版本与血缘 |
| GET | `/api/boards` · `/api/board?version=` | 发布榜单列表 / 单版详情 |
| POST | `/api/drift` · `/api/hyper` | 修改 `drift_sd`（或 `window` 等）配置并重算 |
| POST | `/api/correct` | 更正一场赛果并触发重放 |
| POST | `/api/publish` | 发布当前榜单 |
| POST | `/api/reset` | 删除本地生成物，恢复原始赛果 |

## 测试

```bash
npm test          # 等价于 .venv/bin/pytest -q
```

覆盖内容：

- **生成器**：确定性、真值长度、全部情景存在、方向无关去重、孤立组不混、绑定组总同队、
  缺席空档、平局合理、同队同日不重复对阵、结果簿版本；
- **引擎**：解析梯度 vs 中心差分、单场联合 vs 对角一致性、已知能力恢复、缺席只增不确定、
  观测不会给出先验之外的确信、窗口截断、平局概率归一；
- **重放与榜单**：榜单追加不可变、更正后旧榜单原样、重放从正确检查点开始、窗口滤波重放
  保留前缀、诊断标记孤立/绑定/重复；
- **HTTP**：bootstrap 形状、frames/frame/player、compare+checks、scenarios+diagnostics、
  漂移失效与可复现、超参范围拒绝、发布→更正→旧榜单不变→血缘→再发布、非法 JSON 报错、
  重置只删本地生成物、sweep 形状。
